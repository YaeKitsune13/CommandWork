2.3. Плейлисты
- Создание/редактирование/удаление своих плейлистов

2.5. Добавление своих музыкальных треков на площадку

2.6. Чарты

- Подписка на пользователей/исполнителей

- Комментарии под треками

## Префиксы коммитов (Conventional commits)

Рекомендуемая схема префиксов помогает быстро понимать назначение коммита и встраивается в автоматические релизные/CI-процессы. Формат: `type(scope?): subject`

- feat — новая функциональность
  - Описание: добавляет новую возможность для пользователя или API.
  - Пример: `feat(auth): add login with email`

- fix — исправление ошибки
  - Описание: исправления багов, которые чинят неправильно работающее поведение.
  - Пример: `fix: resolve crash on save`

- docs — документация
  - Описание: изменения только в документации (README, комментарии, спецификации).
  - Пример: `docs(readme): clarify setup steps`

- style — стиль и форматирование
  - Описание: правки, не влияющие на логику (пробелы, форматирование, точки с запятой, линтер-исправления).
  - Пример: `style: apply prettier to src/`

- refactor — рефакторинг
  - Описание: изменения в коде, которые улучшают структуру или читаемость, без исправления багов и без добавления фич.
  - Пример: `refactor(user): extract profile utils`

- test — тесты
  - Описание: добавление или изменение тестов, настройка тестовой инфраструктуры.
  - Пример: `test(api): add integration tests for auth`

- chore — вспомогательные задачи/обслуживание
  - Описание: задачи по поддержке проекта (обновление зависимостей, CI, скрипты), которые не меняют поведение приложения.
  - Пример: `chore(deps): bump react to 18.2.0`

Советы по оформлению:
- Используйте нижний регистр для типа: `feat`, `fix` и т.д.
- Scope (необязательно) указывайте в круглых скобках: `feat(auth): ...`
- Subject в повелительном наклонении и короткий (50–72 символа максимум).
- Добавляйте более детальное описание в теле коммита (если нужно) и, при необходимости, ссылку на issue/задачу.
