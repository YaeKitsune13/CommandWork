# Техническое задание на API

## 1. Общее описание

API является центральной точкой взаимодействия между клиентскими приложениями (Web, Mobile) и сервером. Документ описывает правила, обязательные для соблюдения всеми участниками разработки, независимо от платформы.

### Окружения (Base URL)

| Окружение | URL |
|---|---|
| Dev | `https://dev-api.example.com/api/v1` |
| Stage | `https://stage-api.example.com/api/v1` |
| Prod | `https://api.example.com/api/v1` |

> Версия API указывается в пути (`/v1/`). При breaking changes создаётся новая версия (`/v2/`), старая поддерживается ещё N месяцев (уточнить срок).

---

## 2. Аутентификация и авторизация

- Все запросы, кроме `/auth/login` и `/auth/register`, требуют JWT-токен.
- Токен передаётся в заголовке:
```
Authorization: Bearer <access_token>
```

**Ответ при невалидном:**
```json
{
  "code": "UNAUTHORIZED",
  "message": "Token is invalid or expired",
  "result": null
}
```
HTTP статус: `401`

---

## 3. Общие правила форматирования

### Даты
Формат — **ISO 8601**, всегда в UTC:
```
YYYY-MM-DDTHH:mm:ssZ
Пример: 2026-09-04T12:00:00Z
```

### Именование полей
- **В JSON (запросы/ответы)** — всегда `snake_case`:
```json
{ "user_id": 1, "created_at": "2026-09-04T12:00:00Z" }
```
- **В коде** — по конвенции языка (C# → PascalCase, JS/TS → camelCase). Маппинг на C# выполняется через `[JsonPropertyName("user_id")]` или глобальный `JsonNamingPolicy`.

> Это правило касается только структуры данных в теле запроса/ответа, а не именования переменных внутри кода клиента или сервера.

### HTTP-статусы
Сервер использует реальные HTTP-коды поверх JSON-обёртки:

| Код | Когда используется |
|---|---|
| 200 | Успешный запрос (GET, PUT, PATCH, DELETE) |
| 201 | Успешное создание ресурса (POST) |
| 400 | Ошибка валидации |
| 401 | Не авторизован / токен невалиден |
| 403 | Доступ запрещён |
| 404 | Ресурс не найден |
| 409 | Конфликт (например, email уже занят) |
| 500 | Внутренняя ошибка сервера |

## 4. Формат ответа

Единая обёртка для всех эндпоинтов:

```json
{
  "code": "...",
  "message": "...",
  "result": { }
}
```

| Поле | Тип | Описание |
|---|---|---|
| `code` | string | Внутренний код: `"OK"` для успеха, либо код ошибки, например `"VALIDATION_ERROR"` |
| `message` | string | Человекочитаемое сообщение |
| `result` | object \| array \| null | Данные ответа. `null` при ошибке или отсутствии данных |

### Пример успешного ответа
```json
{
  "code": "OK",
  "message": "User created successfully",
  "result": {
    "user_id": 1,
    "email": "test@example.com",
    "created_at": "2026-09-04T12:00:00Z"
  }
}
```

### Пример ответа с ошибкой (одно поле)
```json
{
  "code": "VALIDATION_ERROR",
  "message": "Validation failed",
  "result": {
    "errors": [
      { "field": "email", "reason": "invalid_format" }
    ]
  }
}
```

### Пример ответа с ошибкой (несколько полей)
```json
{
  "code": "VALIDATION_ERROR",
  "message": "Validation failed",
  "result": {
    "errors": [
      { "field": "email", "reason": "invalid_format" },
      { "field": "password", "reason": "too_short" }
    ]
  }
}
```

## 5. Таблица кодов ошибок

| `code` | HTTP статус | Описание |
|---|---|---|
| `OK` | 200 / 201 | Успешный запрос |
| `VALIDATION_ERROR` | 400 | Ошибка валидации входных данных |
| `UNAUTHORIZED` | 401 | Токен отсутствует/невалиден/истёк |
| `FORBIDDEN` | 403 | Нет прав на действие |
| `NOT_FOUND` | 404 | Ресурс не найден |
| `CONFLICT` | 409 | Конфликт данных (например, дубликат) |
| `INTERNAL_ERROR` | 500 | Непредвиденная ошибка сервера |

*(таблица дополняется по мере появления новых кейсов)*

## 6. Пагинация

Для всех списочных эндпоинтов:

**Запрос:**
```
GET /users?page=1&limit=20
```

**Ответ:**
```json
{
  "code": "OK",
  "message": "OK",
  "result": {
    "items": [ ],
    "pagination": {
      "page": 1,
      "limit": 20,
      "total_items": 134,
      "total_pages": 7
    }
  }
}
```

## 7. Пример эндпоинта (шаблон для заполнения)

### `POST /users` — Создание пользователя

**Заголовки:**
```
Authorization: Bearer <access_token>
Content-Type: application/json
```

**Тело запроса:**
```json
{
  "email": "test@example.com",
  "password": "string",
  "full_name": "string"
}
```

**Модель запроса:**

| Поле | Тип | Обязательное | Описание |
|---|---|---|---|
| `email` | string | да | Email пользователя |
| `password` | string | да | Минимум 8 символов |
| `full_name` | string | нет | Полное имя |

**Успешный ответ `201`:**
```json
{
  "code": "OK",
  "message": "User created successfully",
  "result": {
    "user_id": 1,
    "email": "test@example.com",
    "full_name": "string",
    "created_at": "2026-09-04T12:00:00Z"
  }
}
```

**Возможные ошибки:**

| Код | HTTP | Причина |
|---|---|---|
| `VALIDATION_ERROR` | 400 | Некорректный email или короткий пароль |
| `CONFLICT` | 409 | Email уже зарегистрирован |
