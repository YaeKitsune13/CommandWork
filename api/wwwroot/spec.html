Спецификация API Dinisify (v1)

Единый контракт для бэкенда и веб-клиента. Главное правило: вебу хватает одного запроса на экран и одного парсера на сущность.

1. Ключевые архитектурные решения

Решение Описание для фронтенда
Автор = Пользователь Таблицы artist больше нет. Везде вместо artistId и artistName возвращается вложенный объект owner: { id, nickname, image }.
Единый TrackDto Один и тот же формат трека возвращается везде: в каталоге, поиске, альбоме, плейлисте, истории, лайках, чартах и на модерации.
Единая пагинация Любой постраничный список принимает ?page=1&pageSize=20 и возвращает { items: [], page: 1, pageSize: 20, total: 134 }.
Аудио-стриминг В каждом треке есть поле streamUrl: "/api/tracks/{id}/stream" с поддержкой перемотки (HTTP Range 206).

2. Единый формат ошибок (4xx и 5xx)

Любая ошибка от сервера всегда возвращает одинаковую JSON-структуру: 

{
  "error": "Пользователь с такими данными уже существует",
  "code": "conflict",
  "fields": {
    "email": ["Этот email уже занят"],
    "nickname": ["Этот никнейм уже занят"]
  }
}
HTTP код Поле code Когда возникает
400 validation / bad_request Некорректные поля формы (подробности в fields) или недопустимое действие
401 unauthorized Токен не передан, истёк, либо неверный логин/пароль
403 forbidden / blocked Недостаточно прав (чужой ресурс, гость) или аккаунт заблокирован (blocked)
404 not_found Объект не существует или скрыт настройками приватности
409 conflict Дубликат: email, никнейм, телефон, жалоба, подписка, трек в плейлисте
500 server_error Внутренняя ошибка сервера

Шпаргалка для фронтенда: Экран → Запросы API

Экран приложения Какие запросы делать при открытии
Главная / Обзор GET /api/charts, GET /api/recommendations, GET /api/genres
Глобальный поиск GET /api/search?query=... (возвращает сразу tracks, users, albums, playlists)
Страница трека GET /api/tracks/{id}, GET /api/tracks/{id}/comments?page=1
Страница альбома GET /api/albums/{id} (все треки альбома уже внутри поля tracks)
Страница плейлиста GET /api/playlists/{id} (все треки и соавторы уже внутри)
Профиль пользователя / автора GET /api/users/{id}, GET /api/users/{id}/tracks, GET /api/users/{id}/albums, GET /api/users/{id}/playlists
Кабинет автора («Мои загрузки») GET /api/users/{myId}/tracks?status=pending (или без status — вернет все свои треки вместе с rejectionReason)
Моя медиатека GET /api/users/{myId}/likes, GET /api/playlists/my, GET /api/users/{myId}/history
Панель модератора GET /api/moderator/tracks/pending, GET /api/moderator/complaints?status=pending
Панель администратора GET /api/admin/analytics, GET /api/admin/users, GET /api/admin/genres

Список изменений (От старой версии к v1)

Было (v0) Стало (v1) Примечание
ArtistId при загрузке трека/альбома Удалено Владелец (owner) автоматически берётся из JWT-токена
artistId, artistName в ответах owner: { id, nickname, image } Единый объект автора во всех ответах
GET /api/music/artist/{artistId} GET /api/users/{id}/tracks Также доступен алиас GET /api/tracks/user/{userId}
GET /api/music/meta?id=1 GET /api/tracks/{id} Старый маршрут оставлен как алиас для обратной совместимости
GET /api/music/sound?id=1 GET /api/tracks/{id}/stream Поддерживает перемотку Range
